# FluentCart

Start with `discover_abilities` and filter for FluentCart before changing store data. Inspect every candidate ability with `get_ability_info`, especially product-create/update schemas and destructive annotations. For catalog work, read the current product first, create new products as drafts when the plugin supports status, preserve SKU/pricing/tax data the user did not ask to change, then execute through `run_ability`. For bulk repricing or imports, work in bounded batches and re-read each saved product or a representative sample plus totals. If the installed FluentCart version exposes no Abilities for the requested operation, use only its documented public REST API through hardened `rest_api` / `rest_api_write`; never write private tables or serialized options by guess.
